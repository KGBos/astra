# Design — Distance-Adaptive Visual Fidelity (LOD)

> **Status**: Proposed (Theo Lindqvist 🧭, Shift 1)
> **Blocked by**: perf recovery (Phase 1), material registry (T-09). **Implemented by**: T-13 … T-20.
> **Goal**: detail *emerges* as you approach a surface, the way it does in reality.

---

## 1. The problem, measured

Every texture in the engine is a fixed 8×8 grid (`AsciiTexture`, `textures.py:10`),
sampled with a single nearest-neighbour lookup regardless of viewing distance:

```566:567:src/engine/raycaster.py
        tx = int((hit.wall_x % 1.0) * texture.width)
        tx = max(0, min(tx, texture.width - 1))
```

A wall face projects to `span = ppm / distance × wall_height` character cells. With
`ppm = 57.13` at 160×50 and an 11 m brownstone, one texel covers this many cells:

| Distance | Face height (cells) | Cells per texel |
| ---: | ---: | ---: |
| 2 m | 314 | **39.3** |
| 4 m | 157 | **19.6** |
| 8 m | 79 | **9.8** |
| 16 m | 39 | **4.9** |
| 32 m | 20 | **2.5** |
| 64 m | 10 | 1.2 |
| 128 m | 5 | 0.6 |

The break-even point — one texel per cell, where the art is actually resolved at its
authored resolution — sits at **~78 m**. Everything nearer is magnified. In other words
the *entire playable near field is under-detailed*, and the closer you walk to a
building the worse it gets. At 2 m a single authored texel is smeared across a 39-row
block of identical glyphs.

This is precisely backwards from the goal, and it is the single largest visual-fidelity
defect in the engine. It is not a shading problem, a palette problem, or a lighting
problem. It is a **texture magnification** problem, and it has a well-understood fix.

---

## 2. Design principles

1. **Detail is a function of world position, never screen position.** Any detail keyed
   on screen coordinates will crawl and shimmer as the camera moves. This is the one
   property that, if violated, makes the whole feature worse than no feature.
2. **Coarser levels must be consistent with finer ones.** Level *n* must look like
   level *n−1* with detail added, not like different art. Otherwise transitions pop.
3. **Cost scales with what you can actually see.** Near-field detail work must be
   range-gated so distant geometry never pays for it.
4. **Every level degrades to pure ASCII.** The `--no-color` transliteration contract
   (`tests/test_render_modes.py`) is non-negotiable and must hold at all levels.

---

## 3. Architecture

### 3.1 `MipTexture` — the pyramid

Replace `AsciiTexture` with a pyramid of levels at 8, 16, 32, 64, 128 texels square
(L0–L4). L0 is the existing hand-authored art, unchanged, so **distant views look
exactly as they do today** — this refactor cannot regress the skyline.

Storage matters. A naive L4 (128² texels × char + two RGB tuples) costs roughly 2 MB
per material in CPython, and we have a dozen materials. Instead store each level as:

- `chars`: a single `str` of length `w*h` (index with `y*w + x`)
- `fg_idx`, `bg_idx`: `bytearray` palette indices, one byte per texel
- `palette`: a shared `list[tuple[int,int,int]]` per material, ≤256 entries

That is ~48 KB for a full L0–L4 pyramid per material, and `bytearray` indexing plus a
list lookup is faster in the hot loop than tuple unpacking from nested lists. Colour
interning also lets the shading LUTs in `tone.py` key on palette index rather than RGB.

**Levels are built lazily on first use and cached**, so a scene that never shows a
warehouse never pays for warehouse mips.

### 3.2 Level selection

Computed **once per column**, not per pixel:

```
span        = rows_per_m * hit.wall_height     # already computed at raycaster.py:510-512
texels_want = span / TARGET_CELLS_PER_TEXEL    # target = 1.0
level_f     = log2(texels_want / 8.0)          # 8 = L0 size
level_f     = clamp(level_f, 0.0, 4.0)
```

`log2` per column is ~160 calls per frame — negligible. If profiling disagrees, quantise
`perp_wall_dist` into 64 buckets and use a precomputed table.

At 160×50 this yields:

| Level | Size | Engages at |
| :--- | ---: | :--- |
| L0 | 8² | beyond 78 m |
| L1 | 16² | 39–78 m |
| L2 | 32² | 20–39 m |
| L3 | 64² | 10–20 m |
| L4 | 128² | nearer than 10 m |

### 3.3 Cross-fade without popping

`level_f` is fractional. Rather than blending two texture fetches (double the sampling
cost), **dither between the two neighbouring levels** using the Bayer matrix already
present in `tone.py`:

```
lo = int(level_f); frac = level_f - lo
use_hi = BAYER4[x & 3][y & 3] < frac
level  = lo + 1 if use_hi else lo
```

One fetch, no blend arithmetic, and in a character grid the stipple reads as natural
surface grain rather than as an artifact. This is the right trilinear analogue for the
medium and it is essentially free.

### 3.4 World-anchored detail synthesis

Levels above L0 are generated by upsampling the level below and adding a detail octave.
The detail function is hashed on **material identity and texel coordinates within the
material's own UV space** — never on screen or camera state:

```
h = hash_noise(material_id * 8191 + level, tx, ty)
```

Because `tx`/`ty` derive from `hit.wall_x` (a fractional *world* coordinate) and the
vertical world position on the face, detail is pinned to the surface. Walk toward a
wall and the same brick stays the same brick, growing larger and gaining sub-detail.
Walk sideways and nothing crawls.

The upsample rule preserves principle 2: a 2×2 block in level *n* averages back to its
parent texel in level *n−1* in both glyph density and colour, so a dithered transition
between the two is statistically invisible.

### 3.5 Near-field decal layer

Procedural noise gives *texture*; it does not give *features*. Below `DECAL_RANGE`
(≈12 m) each material may declare a decal table — door handles, buzzer panels, signage,
grime streaks, cracks, rivets, AC units, fire escapes, meter boxes. Placement is
deterministic on world cell coordinates `(map_x, map_y, side)`, so a given building
always has its handle in the same place.

Decals composite over the mip sample and are only evaluated inside the range gate, so
the skyline pays nothing. This is what makes a wall read as *a specific door* rather
than as a well-textured rectangle, and it is where most of the perceived realism win
actually lives.

### 3.6 Sub-cell resolution

Even L4 leaves ~2.5 cells per texel at 2 m. To close the last stretch, below
`SUBCELL_RANGE` (≈5 m) encode a 2×2 coverage mask per cell using quadrant block glyphs
(`▘▝▖▗▀▄▌▐▚▞█`), doubling effective resolution on both axes. This requires:

- a 16-entry coverage-mask → glyph table
- transliteration entries so `--no-color` still degrades to pure ASCII

Colour mode already preserves Unicode by contract
(`test_render_modes.py:21`), so this fits the existing render-mode architecture
rather than fighting it.

### 3.7 Parity across surface types

Walls are the pilot. The same selection function must then be applied to:

- **Floors/ceilings** — the floor caster already knows `row_distance`; LOD slots in
  directly and the payoff is large, since ground fills the lower half of the frame.
- **Sprites** — a resolution ladder per sprite (silhouette → detailed → close-up),
  selected on the same distance metric. A pedestrian at 2 m should show a face.

## 4. Performance

LOD is not free, but it is close to net-neutral because the per-pixel cost is unchanged:
one array index into a larger array. The additions are one `log2` and one Bayer compare
per column, and the range-gated decal/sub-cell passes.

**Hard requirement**: this work lands *after* Phase 1 perf recovery, and the benchmark
matrix must still clear 60 FPS at 160×50 with LOD enabled. If it does not, the level cap
becomes viewport-adaptive (see the adaptive-quality ticket, T-25) rather than the feature
shipping over budget.

## 5. Verification

A refactor of the sampling path can silently change every pixel on screen, so this work
needs a guard rail that ordinary unit tests do not provide:

1. **Golden-frame harness (T-02, lands first).** Byte-exact framebuffer snapshots at
   fixed seed, position, time of day, and weather. With LOD disabled, every golden frame
   must be unchanged — that is what proves the refactor is safe.
2. **Distance-monotonicity test.** Measure distinct glyph count over a wall face at 64 m,
   32 m, 16 m, 8 m, 4 m. It must increase monotonically. This is the automated statement
   of the actual feature.
3. **No-crawl test.** Translate the camera parallel to a wall in small steps; the glyph
   at a fixed *world* point on that wall must not change. This catches screen-space
   detail leaks, the failure mode from principle 1.
4. **ASCII purity.** Existing `test_render_modes.py` assertions must pass at every level.
5. **Mip consistency.** Downsampling level *n* must reproduce level *n−1* within a
   tolerance, enforcing principle 2.
